# 专题：存档目录结构（按战斗指纹分组，自动/手动分离）

状态：设计稿（待用户审定后实现）。2026-10-11 20:1x 用户裁定演进：①曾定"一战斗一文件多存档点容器"（追加+索引直跳）；②随后推翻——**单文件内多存档点一旦文件损坏会连坐全部存档点**，改回**多文件设计：一个文件只放一个存档**（单档损坏互不影响，写入本就 tmp+rename 原子）；③保存目标结构调整：存档根目录下新增**战斗指纹目录**，内分 `自动/` 与 `手动/` 两个子目录；`自动/` 用法后定（本轮预留空置），**当前按 G 的存档全部放 `手动/`**。

## 1. 背景与问题

- 现状：所有存档平铺在存档根目录，文件名 `<64hex 指纹>_<yyyymmdd>_<hhmmss>[_<撞名序号>].hbs`；同场战斗的多次存档靠文件名前缀人工辨认。
- 问题：①存档数量多时目录混乱，同场战斗的档散落；②将来自动存档与手动存档混在一起无法区分用途。
- 已否决方案（留档防复发）：单文件多存档容器（Record+Index+Footer，见本文档 git 历史 b97838d 版本）——追加/直跳性能达标，但**单点损坏连坐全部存档点**，用户裁定不可接受。

## 2. 目标与非目标

**目标**
1. 按战斗指纹分组：同场战斗的全部存档落同一子树，天然聚合。
2. 自动/手动分离：按 G 手动存档进 `手动/`；`自动/` 为后续自动存档策略预留。
3. 单档单文件 + 现有帧格式与原子写（tmp+rename）不变——损坏隔离由多文件天然获得。
4. 读档语义不变：读"最新存档点"= `手动/` 内最新文件。

**非目标**
- 不改单档文件格式（帧结构、codec v8 载荷、CRC——全部沿用）。
- 不做 `自动/` 的写入/清理策略（用法后定）。
- 不做旧存量档迁移/兼容列举（根目录直下的旧 `.hbs` 留盘不删、不进读档视野）。
- 不做存档点列表选择 UI（后续再议）。

## 3. 目录布局（v1）

```
<存档根>\
  <64hex 战斗指纹>\
    手动\
      <yyyymmdd>_<hhmmss>[_<撞名序号2..999>].hbs    ← 一档一文件，现有帧格式
    自动\                                             ← 本轮预留（空置，不写入）
```

- 指纹目录名 = 现有 64hex 场次指纹（[02-指纹与存档索引](02-指纹与存档索引.md)），首次存档时创建。
- 文件名去掉指纹前缀（目录已表达），保留日期/时间/撞名序号——同秒多次存档仍不覆盖。
- `手动/` 内文件按时间戳排序即存档点顺序，最新=读档目标。

## 4. 读写路径

**存档（按 G）**：指纹目录不存在则创建（`手动/`/`自动/` 同时建齐）→ 现有编码 → `手动/<时间戳>.hbs` tmp+rename 原子落盘。撞名（同秒）沿用现有序号规则。

**读档**：枚举 `手动\*.hbs` 按时间戳取最新 → 现有单档读取与校验（指纹一致性、CRC、结构界）完全不动。

**列举/管理**：玩家手动清理 = 删 `手动/` 内文件或整个指纹目录；`自动/` 出现文件不影响当前读档视野。

## 5. 崩溃与损坏语义

- 写入：tmp+rename 原子（现状），写坏不产生半档。
- 单文件损坏：只丢该存档点，其它档与同场全部存档点不受影响（多文件天然隔离——本轮裁定核心动机）。
- 指纹目录/子目录创建中断：下次存档重建目录，无残留状态。

## 6. 接口与改造点（实现轮）

1. `BattleArchive.inc.cpp`：存档路径拼接改 `<根>\<指纹>\手动\<时间戳>.hbs`；目录创建（含 `自动/` 预留）；列举改枚举 `手动\*.hbs`；`ParseGeneratedName` 相应调整为"目录名=指纹 + 文件名=时间戳"。
2. `BattleStoreService.inc.cpp`：存档目标与读档来源同步切换；根目录直下旧 `.hbs` 不再进入读档视野。
3. 测试（`tests/ArchiveTests.cpp` 扩展）：首存建目录树（含空 `自动/`）；同秒撞名序号；读最新；旧根目录档不列举；损坏单档不影响读取更新的档。
4. UI/键位/流程不动。

## 7. 风险与边界

- **重打同场战斗**（同指纹、不同 generation）：存档继续落同一指纹目录；档内 generation 校验（现有）保证读档一致性，最新点天然正确。
- **指纹碰撞**（理论极小）：异场战斗共目录，读档时指纹一致性防线拒绝错档（现有机制）。
- **目录层级变深**：路径拼接仍走堆缓冲 `kPathCap_`（项目规范），无栈风险。
- **`自动/` 语义未定**：本轮只建不写；将来定策略时只改写入侧，读档/列举按届时裁定扩展。
