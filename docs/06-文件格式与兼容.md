# 专题：文件格式与兼容

> 来源：原《设计文档.md》§10（2026-10-08 按用户裁定拆分）。
> 实际 v6 帧布局与拒绝策略以 `BattleArchive.inc.cpp`/`BattleCodec.inc.cpp` 及独立 Archive/Codec 测试为准。

## 1. 目录与文件名

每条记录一个独立文件，按HD规则取得地图/游戏名目录，再增加固定子目录"战场存档"（2026-10-06 最新裁定，取名链与HD `UI.Ext.ScenarioMgr.Folders=1`相同，但不再与过天自动档混放）：

```text
<游戏目录>\Games\<游戏名>\战场存档\                  单人遭遇战游戏名=地图名（含 {~c} 颜色码）；热座=玩家输入
  6ecad1ad...822dba8_20261006_192213.hbs             战斗指纹_本地年月日_时分秒
  6ecad1ad...822dba8_20261006_192213_2.hbs           同指纹同秒撞名追加 _2、_3…
<游戏目录>\Games\Unnamed\战场存档\                   随机图等无名的局（对齐 HD s_Unnamed 默认）
```

目录由 `ArchiveRoot_()` 每次现算：从 DLL 路径向上定位含 `Games` 的游戏根，再读当前局游戏名——`*(char**)(*(DWORD*)0x699538 + 0x1fb40)`，与 HD SaveGame 后置钩子（HD_SODSrc:191556-191640）取目录名的链完全一致；NULL/空白 → "Unnamed"；含非法字符（`..`、`:`、控制字符、通配符等）或链不可读退回 `Games\战场存档\`。最终路径始终增加"战场存档"子目录，无缓存，避免跨局残留。2026-10-06 本机旧目录4条档已手工迁入子目录并核验SHA256不变；插件仅扫描新目录，不做通用自动迁移。文件名时间为本地时间（秒精度），仅检查格式及日历有效性，不依赖当前系统时区反算身份；文件头UTC毫秒和CRC为权威，改时区不使有效档消失。列表、保存成功提示和读档确认统一通过 `FormatLocalArchiveStamp` 调用与文件命名相同的 `UtcMsToLocalSystemTime`，以 Windows 当前本机时区（含夏令时）呈现，禁止直接 `gmtime` 或固定加8小时；既有文件名保持保存时的本地标签，不重命名；`sequence`/`targetKey` 不进文件名（保留在头内）。保存成功后立即重绘常驻普通列表，第一项为刚存的档（按时间戳倒序天然满足）。

## 2. 负载编码原则

负载采用显式小端字段和长度前缀，不把 C++ 结构体直接写盘。

实际帧结构（magic/version/headerSize/双指纹/UTC 毫秒/sequence/sectionCount/分段/全文件 CRC）见《[02-指纹与存档索引](02-指纹与存档索引.md)》第 2 节，以 `BattleArchive.inc.cpp` 为准。

版本策略（2026-10-07 用户裁定）：任何破坏字段布局、所有权规则或随机语义的升级都必须 bump 段内 codec 版本（当前 v6），旧档一律拒绝读取、不尝试"猜字段"兼容，也不自动删除旧文件；archive 容器层 formatVersion 仍为 1。

## 3. 写入与保留策略

写入采用：`*.tmp` → `FlushFileBuffers` → `MoveFileExW(MOVEFILE_WRITE_THROUGH)` 原子替换，失败删除 tmp。清理策略先按每场 30 条，再按最近使用的 30 场；删除失败不影响当前游戏，只记录警告。
