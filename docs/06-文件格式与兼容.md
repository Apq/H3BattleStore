# 专题：文件格式与兼容

> 来源：原《设计文档.md》§10（2026-10-08 按用户裁定拆分）。
> 实际 v8 帧布局与拒绝策略以 `BattleArchive.inc.cpp`/`BattleCodec.inc.cpp` 及独立 Archive/Codec 测试为准。

## 1. 目录与文件名

2026-10-11 21:11 起（指纹目录布局落地）：存档根仍按 HD 规则取得地图/游戏名目录 + 固定子目录"战场存档"，其下按**战斗指纹分目录**组织：

```text
<游戏目录>\Games\<游戏名>\战场存档\
  <64hex 战斗指纹>\
    手动\   <回合数>_<编号>.json|.hbs     一档一文件；按 G 存档全部落此
    自动\   <回合数>.json|.hbs            每回合首个玩家等待自动存；最近30档
<游戏目录>\Games\Unnamed\战场存档\...     随机图等无名的局（对齐 HD s_Unnamed 默认）
```

- 手动文件名 = `<存档时刻回合数>_<编号>`（自动文件名仅 `<回合数>`）：编号为同回合内存档序号，从 1 起、取同回合已有最大编号 +1，**自然位数无上限不补零**；`(回合, 编号)` 唯一，无历史 999 容量限制。列表按 (回合, 编号) 两段数值倒序（详见《[02-指纹与存档索引](02-指纹与存档索引.md)》§3）。
- 后缀由 `user.ini [Store] saveFormat` 决定（`binary` → `.hbs`（默认），`json` → `.json`）；列举/存/读三处同源，两后缀互不可见，旧档留盘不删不迁移。
- 旧平铺命名（`<指纹>_<日期>_<时间>.hbs` 及同秒 `_2` 撞名后缀）为 2026-10-11 前布局，存量档留盘不删、不进读档视野。

目录由 `ArchiveRoot_()` 每次现算：从 DLL 路径向上定位含 `Games` 的游戏根，再读当前局游戏名——`*(char**)(*(DWORD*)0x699538 + 0x1fb40)`，与 HD SaveGame 后置钩子（HD_SODSrc:191556-191640）取目录名的链完全一致；NULL/空白 → "Unnamed"；含非法字符（`..`、`:`、控制字符、通配符等）或链不可读退回 `Games\战场存档\`。最终路径始终增加"战场存档"子目录，无缓存，避免跨局残留。文件头 UTC 毫秒为权威时间，改时区不使有效档消失；列表行显示与保存成功提示统一通过 `FormatLocalArchiveStamp`/`FormatNumberedArchiveStamp` 调用与命名相同的 `UtcMsToLocalSystemTime`，以 Windows 当前本机时区（含夏令时）呈现，编号为自然位数 `_N` 后缀。保存成功后立即重绘常驻普通列表，第一项为刚存的档（同回合编号最大天然满足）。

## 2. 负载编码原则

负载采用显式小端字段和长度前缀，不把 C++ 结构体直接写盘。**2026-10-11 起双格式并存**：`binary` 路径负载编码原则不变（下述）；`json` 路径为逐字段原子展开的 JSON 文档（无分隔符伪打包、无 base64/hex 字节包），帧结构 `{"format":"H3BS","version":1,…,"sections":{8 段}}` 与字段映射详见《[02-指纹与存档索引](02-指纹与存档索引.md)》§2，JSON 格式版本独立从 1 起。

二进制帧结构（magic/version/headerSize/双指纹/UTC 毫秒/sequence/sectionCount/分段/全文件 CRC）见《[02-指纹与存档索引](02-指纹与存档索引.md)》第 2 节，以 `BattleArchive.inc.cpp` 为准。

版本策略（2026-10-07 用户裁定）：任何破坏字段布局、所有权规则或随机语义的升级都必须 bump 段内 codec 版本（当前 v8），旧档一律拒绝读取、不尝试"猜字段"兼容，也不自动删除旧文件；archive 容器层 formatVersion 当前为 2（2026-10-10 用户裁定升版：codec v7→v8 与 formatVersion 1→2 同步生效，存量档全部拒绝，玩家重新存档）。**JSON 帧版本号独立于二进制两侧版本号，从 1 起、自行递增（2026-10-11 裁定）**；段数据模型两格式共用（双序列化后端，同一 `CodecCapture`），字段增删时二进制 codec 版本与 JSON 帧版本各自升版。

v8 英雄段（section 6）共74字节：`U32(version)`，随后双方各 `U16(mana) + U8(heroPresent) + 4*(I32(artifactId)+I32(subtype))`。四条按穿戴槽13–16保存，对应弩车4、弹药车5、帐篷6、投石车3，空条为(-1,-1)；英雄不存在时四条必须为空。读档拒绝错误机器槽ID和截断段；`heroPresent>1` 独立检查已删除（2026-10-10 用户裁定，仅按 `==1` 解释）。**v8 起法力（spellPoints）唯一存于本段**：battle 段原 `2×U16(mana)` 重复字段已删除，两段一致性比较随之取消。剩余弹药仍由部队段 `infoCombat[6]` 存储，不增加第二份弹药字段。

## 3. 提交写入与档案保留

手动写入采用：唯一 `*.tmp` → `FlushFileBuffers` → `MoveFileExW(MOVEFILE_WRITE_THROUGH)` 提交到唯一新档文件（后缀随配置），失败删除本次 tmp；不得覆盖已有手动档案，不称为“原子替换”。自动档同一管线，但提交加 `MOVEFILE_REPLACE_EXISTING`：`自动\<回合>` 同回合再次保存原子替换旧档。已有 tmp 不覆盖也不删除。两槽均按需回读刚提交的档案（二进制比逐段字节与 CRC；JSON 比解析后的文档树并重新解码）。

手动档永久保留；自动档每次提交后按帧内 UTC 毫秒保留最近30个有效档（仅当前指纹、当前后缀；刚提交档优先保留，防校时回退影响回读），详见《[02-指纹与存档索引](02-指纹与存档索引.md)》§4。未知文件、坏档、旧格式和指纹失配档案不自动删除。文件层扫描结果仅保存 metadata，不缓存所有档案 payload，实际读档按记录路径按需加载和校验。codec v8、容器 formatVersion=2、单档64MB与最多16段的格式限制保持不变（JSON 档同样受 64MB 上限）。读档侧不再独立校验键格式（64hex）与记录四元组一致性（2026-10-10 用户裁定）：非64hex的battleKey不可能等于当前指纹，键比较自然拒绝；**文件名↔内容身份校验改为 `ParseNumberedName` + 帧内 turn 冗余校验（JSON 档不一致隐藏并拒绝；二进制档无帧内回合，以文件名为准）**继续保留。

手动档同回合编号为自然位数、取已有最大编号 +1，无上限；自动档没有编号，文件名仅含回合。同回合自动档可覆盖，手动档不覆盖。日志最多保留30个、自动档最多保留30个是独立策略，手动档不清理。
