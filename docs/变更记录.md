## 2026-10-15

- **单元测试迁移到 Catch2 v3（amalgamated）**：按用户要求参照 H3Space 工程把五组独立单元测试从"自带 `main` + 手写 `Expect/Check` + 进程退出码"改为 Catch2 v3 amalgamated（`third_party/catch2/catch_amalgamated.{hpp,cpp}` 原样入库，与 H3Space 同一份副本）。运行入口仍是 `tests/run-unit-tests.ps1`，改为：先把 `catch_amalgamated.cpp` 编译一次成 `tests/unit-tmp/catch2.obj`（源码更新才重编，避免五套各编一次 46 万字节大文件），再逐组用 `cl /nologo /EHsc /std:c++17 /utf-8 /W4 /wd4505 /O2 /D_CRT_SECURE_NO_WARNINGS /Ithird_party\catch2` 把 `tests\<组名>Tests.cpp`（LogControls 另加 lzma 三个 `.c` 与 `/DZ7_ST /Ilzma`）与该 obj 链接成 `tests\unit-tmp\<组名>.exe` 运行，退出码非零即失败。转换口径分两类：**AltTail（7 用例）、UiPort（3 用例）、LogControls（3 用例）全量重写**为 `TEST_CASE` + `CHECK/REQUIRE`（保留全部断言与描述文本，LogControls 的 fixture 目录从 `argv[1]` 改为环境变量 `H3BS_TEST_FIXTURE`，因为 Catch2 接管了命令行解析）；**Archive（12 用例）、Codec（6 用例）保体换壳**——`Test*` 函数体与断言逐字不动，只把 `Expect(bool,const char*)` 改成 `INFO(name) + CHECK(cond)` 转发、把 `main` 的调用序列拆成对应 `TEST_CASE`（Codec 的内联大块共享局部夹具，保持为单个用例、原序执行）。三个坑记录：①本版 amalgamated **没有 `CHECK_MESSAGE`/`REQUIRE_MESSAGE`**，且表达式分解器拒绝断言顶层 `&&`/`||`，故测试文件自定义 `REQUIRE_MESSAGE(cond,msg)`/`CHECK_MESSAGE(cond,msg)` 包装宏（`INFO(msg)` + `REQUIRE((cond))`，条件必须整体加括号）；②**LogControls 剪贴板替身必须经 `GlobalLock(handle)` 取数据指针**（`GMEM_MOVEABLE` 的 handle 本身不可解引用），转换时漏掉这步会让替身读到堆元数据并 `abort()`，在 Catch2 下表现为进程级 `0xC0000409` 快速失败、无任何报告——替身的不符预期断言已改为 Catch2 断言以便报告；③Catch2 的用例选择器按逗号切分，**名字里带逗号的用例不能用字面量选中**（用通配符，如 `*severity*`）。另：因 Catch2 直接 include 生产 `.inc.cpp`，本迁移未触碰任何生产代码。结果：五组全绿 exit 0（Archive 217 断言/12 用例、Codec 4224/6、LogControls 30167/3、UiPort 39/3、AltTail 14/7）；`third_party/catch2/` 为新增（该副本沿用 H3Space 的 LF、无 BOM，与本仓库自写文件的 CRLF 规则不同，保持拷贝一致）。

- **战场外固定条改用私有快照（切到战场内后左上角残影修复）**：玩家实测"从战场外切到战场内时，战场外那条由于渲染方式不同，残影会一直存在"。日志显示清场**跑了且矩形正确**却无效：`[Ui] native bar erased x=8 y=8 w=480 h=84`。原因在恢复源：老路径（`UiNativeTailErase_` 与 `UiDrawBar_` 内 2026-10-05 的 rectChanged 子矩形清理）把 `screenPcx16` 当战场外的干净源拷回 backbuffer，但呈现之后该矩形里已含插件自己的像素，拷回等于把残影原样写回去。正解与折叠界面同款：**战场外固定条也自持覆盖区快照**（新增 `g_underBar` 槽，`UiUnderCaptureSlot_` 从 backbuffer 抓取、`UiUnderRestoreSlot_` 原样写回 + `H3Redraw`），与 `screenPcx16` 语义彻底解耦——原生 `H3CombatMonsterPanel` 在战场外的无残影机制本就是"覆盖前拷底图、隐藏时贴回"的底图快照三段式（见 H3Note《战场外控件无残影绘制逆向笔记》）。约束与面板完全一致：**只在矩形变化帧、blt 之前捕获**（连续同矩形帧的 backbuffer 已是上一帧的条像素，拍到即拍到自己，写回就是彩条）；整块矩形（含标题行与双列）一次捕获/写回，替代原先按子矩形逐个清的五段逻辑；快照随界面切换释放，并随换场（`OnBattleReset`）与读档成功（`ProcessRestore`）经 `UiUnderInvalidate_` 作废。`UiNativeTailErase_` 保留 screenPcx16 老路径作为"从未捕获成功"时的 best-effort 兜底，并在日志里区分 `source=save-under` / `source=screenPcx16`。验收：默认与 NULL 两个 Rebuild 均 exit 0、0 警告 0 错误（默认 476160B SHA256 `D18BA3BD…AD4D4D`、NULL `D37A5243…6E2400CA`）；五组单测全过 exit 0（40 秒）；已部署（Release 与游戏 Packs 哈希一致）。界面外观与"两个方向互切都不留残影"由用户实机验收。

- **战场外固定条残影二修：单帧写回不够，改多帧重复写回 + 指纹诊断**：一修（私有快照 `g_underBar`）部署后玩家实测"整块内容仍然残留（但已无法点击）"，而日志证明清场**跑了且矩形正确**：`[Ui] native bar erased source=save-under x=8 y=8 w=480 h=84`。逆向复核呈现链定案上屏源：`H3WindowManager::H3Redraw`（`0x603190`）在 `*(char*)(wnd+0x48)==0` 时把矩形（其内部还会把矩形钳到 800x600 逻辑屏）交给 `FUN_00600430`，后者先 `Unlock` 插件写入的那张 DD 表面 `DAT_006aad28`（`*(LPDIRECTDRAWSURFACE*)0x6AAD28`），再用 `ClientToScreen` 换算并对 HD 视口裁剪后 blt 上屏——**上屏源就是插件写入、也是快照写回的那张表面，两者坐标同源**，所以"写了却没效果"只可能落在两种情形：①快照基线本身是脏的（捕获晚于自己绘制）；②写回被随后几帧重新合成盖掉。二修对两种情形各下一手并留诊断：**①多帧重复写回**——`UiUnderRestoreSlot_` 拆出 `UiUnderRestoreSlotEx_(slot, release)`，清场时以 `release=false` 写回并**保留快照**，置 `g_nativeEraseTicks=30`，由分发器 `UiPortDispatch_::Draw` 每帧调 `UiNativeEraseTick_` 继续写回，最后一帧才释放；玩家切回战场外界面时由 `UiApplyOutsideBar_` 取消 tick 并作废旧快照，绝不擦掉新画的条。**②采样指纹诊断**——新增 `UiRectFingerprint_`（每 4 像素采样 FNV-1a，32/16bpp 自适应，`GUARD_COPY` 铠甲内取指纹），捕获帧记 `fp_before`（即将入库的基线）与本帧 blt 之后 `fp_after`，落 `[Draw] bar snapshot x=.. y=.. w=.. h=.. fp_before=.. fp_after=.. 基线脏=?`；清场时记 `fp_now`/`fp_after` 进 `[Ui] native bar erased` 行——**两者相同＝快照里存的就是插件自己画的条（基线脏），不同＝写回没落到画面上**。另加一次性 `[Ui] DD 表面 WxH bpp=.. pitch=.. 合成面=WxH`，把"插件写入的表面到底多大"从推断变实测（此前只能从 `画面=1820x900` 间接猜），并给每帧 tick 补 `[Ui] native bar erase ticks done` 收尾行。验收：五组单测全过 exit 0；默认与 NULL 变体 Rebuild 均 0 警告 0 错误；已部署（Release 与游戏 Packs 哈希一致 `8550DBD0BFF9619D72A603DBF79FF56DDDAE716113E20DAE1CE1BCAF632558B7`，477696B）。残影是否消失、以及指纹落在哪种情形的判读由用户实机验收（agent 不跑游戏）。**用户实机确认（20:4x）：切到战场内后残影消失，本条修复有效**。反推根因（推断，基于修复生效）：若快照基线是脏的，多帧重复写回会把残影每帧反复贴回，玩家不可能看到消失 ⇒ **基线是干净的，真凶是"单帧写回被随后几帧的呈现重新合成盖掉"**，多帧重复写回正是针对该情形。方法已沉淀为技能 `h3-plugin-overlay-no-ghost`（项目作用域，含 save-under 捕获纪律、多帧重复写回、采样指纹判读与呈现链事实）。
