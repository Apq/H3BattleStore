# 专题：界面与功能分离（重构设计）

> 状态：设计定稿（2026-10-10，第 11 节四处开放问题已经用户裁定）。按第 8 节分批实施，第 1–7 步均已完成。
> 分离目的：以后可以整套替换界面（换皮肤、无界面变体），功能层不动；第 7 步（2026-10-14）起玩家可选的两套界面同在一个 DLL，由配置 `[Ui] OutsideBattlefield`（面板第一行「战场外」复选框）选择，默认战场内折叠灯；NullUi 仍为编译期诊断变体。
> 现有契约不变：档案格式 v8/v2、恢复事务语义、CrashGuard 铠甲、默认 debug 日志、用户 ini 键名。

## 1. 目标与非目标

### 1.1 目标

- 界面（绘制、手势、悬停、命中吞并、确认框、改键交互框）与功能（保存/读档请求、列表数据、恢复事务调度、日志级别、日志打包、热键持久化）彻底分层，中间只经一个显式契约。
- 钩子入口（Entry.inc.cpp）不再读写界面内部状态（`g_ui.*` 直接触碰清零），只调用契约。
- 现有 HD 原生悬浮条整体迁移为契约的一个实现（HdNativeUi），外观与交互逐像素、逐行为不变。
- 提供第二个实现 NullUi（无界面、只记日志）用于单元测试和未来“无界面运行”。
- 每一步迁移可独立编译、回归、回退；不做一次性大爆炸重写。

### 1.2 非目标

- 不改档案格式、codec、恢复事务、时机窗口判定逻辑本身。
- 不改任何钩子挂载点、原函数调用次数与异常传播语义（原函数仍在插件 `__try/__except` 之外恰好一次）。
- 不在本轮引入新界面（外部工具等），只留扩展点。
- 不改配置键名、默认值和 user.ini 覆盖优先级。

## 2. 现状耦合盘点（事实清单）

以 2026-10-10 代码为准（行号会漂移，以函数名为锚点）：

1. **功能住在 UI 文件里**。`BattleUi.inc.cpp` 同时包含：
   - 列表数据与扫描：`UiSaveEntry` 结构、`g_ui.entries`、`UiReloadEntries_`（调 `BattleFingerprint_` + `hbs::ArchiveStore::List`）；
   - 读档请求状态机：`g_restoreRequest`（pending/generation/requested/battleKey/entry）、`UiConfirmAndRestore_`、`UiExecuteRestore_`、`UiMaintainRestore_`、`UiProcessRestore_`；
   - 玩家文案目录：`UiRestoreReasonZh_`（领域错误串→中文，约百条）；
   - 日志级别选择与持久化：`UiSelectLogLevel_`→`SaveLogLevel_`；
   - 日志打包入口：`UiPackLogs_`→`PackRecentLogs_`；
   - 热键与位置持久化：`UiKeyIsFree_`、`UiSaveHotkey_`、`UiLoadBarPosition_`、`UiSaveBarPosition_`；
   - 通知状态：`UiMarkSaved_`/`UiMarkNotice_`/`UiMarkNoticeHighlight_`。
2. **钩子层直接触碰界面内部**。`Entry.inc.cpp` 里 60+ 处直接读写 `g_ui.saveKey/awaitingRebind/rebindKey/rebindGuardUntil/scroll/listGesture/listRightHeld/hoverRow/logLevelHover/entries`，分布在键盘钩子、鼠标钩子、消息钩子、`CombatCycleAfter_` 绘制帧、`BattleReset_`、保存路径（`TrySave_`、保存完成后的 `UiMarkSaved_`/`UiReloadEntries_`）。
3. **双输入路径互备**：消息钩子（0x473A00）与系统钩子（WH_KEYBOARD/WH_MOUSE）+ 绘制帧 `GetAsyncKeyState` 兜底并存；物理边沿经 `g_saveEdgeConsumed` 闩锁去重；鼠标点击经 `g_pendingClickX/Y`（Interlocked）投递到绘制帧消费。
4. **时机窗口是共享门禁**：`CombatStorageWindow_`/`CombatPlayerWindow_` 同时被保存路径（Entry）与读档请求（BattleUi）使用，属于功能策略，不属于界面。
5. **绘制完全原生**：`UiDrawBar_`（字体/PCX 合成/DD backbuffer 拷贝）、`UiBltPcx16Region_`、`UiCopyBgRegion_`、`UiLoadBg_`、`UiLayout.hpp` 纯几何。这部分是纯界面。

## 3. 目标分层

```text
钩子层 Entry.inc.cpp（不变：HiHook/LoHook/系统钩子 + Guard 铠甲）
   │  只做三件事：透传判定委托、原函数恰好一次、把原生输入翻译成契约事件
   ▼
界面契约 BattleUiPort.hpp（IBattleStoreUi，纯抽象接口）
   │  实现 A：HdNativeUi（战场外左上角固定条，`[Ui] OutsideBattlefield=1`）
   │  实现 B：FoldableBarUi（战场内右上角折叠灯，默认 `0`）
   │  实现 C：NullUi（诊断变体，编译宏 `H3BS_UI_NULL`）
   │  A/B 同在一个 DLL，由运行期分发器 UiPortDispatch_ 按配置选择（第 7 步）；Entry 只认 g_uiPort
   ▼
领域服务 BattleStoreService（功能核心）
   │  保存/读档请求、列表数据、恢复调度、日志级别、打包、热键策略
   ▼
既有底层（ArchiveStore / Codec / RestoreTransaction / Fingerprint / LogPack / IniUtf8）
```

判定口径：**凡是“换一套界面后仍然成立”的就是功能**（列表内容、请求状态机、文案映射、热键占用表、存读档门禁）；**凡是“换界面就没了”的就是界面**（像素、手势、悬停高亮、确认框形式、GBK 转换、通知显示时长）。

## 4. 界面契约（BattleUiPort.hpp 草案）

```cpp
// 只在游戏主线程调用（含各钩子回调与绘制帧）；跨线程输入沿用现有
// Interlocked 投递（g_pendingClickX/Y、g_saveEdgeConsumed），不新增线程入口。
// 事件结构一律 POD：实现方法可能在 SEH 保护体内被调用，禁止要求展开。
struct UiKeyEvent_   { int vkOrLetter; bool down; bool repeat; int source; }; // source: msg/system-frame
struct UiMouseEvent_ { int gameX, gameY; int kind; };  // kind: move/lDown/lUp/rDown/rUp/wheel
struct UiFrameTick_  { DWORD tick; int cursorX, cursorY; };

class IBattleStoreUi {
public:
    virtual ~IBattleStoreUi() {}
    // ---- 输入事件（返回 true = 吞并不透传战场）----
    virtual bool OnKey(const UiKeyEvent_& e) = 0;        // 键盘钩子+消息钩子+帧兜底统一入口
    virtual bool OnMouse(const UiMouseEvent_& e) = 0;     // 系统鼠标钩子路径
    virtual void OnFrameClick(int gameX, int gameY) = 0;  // 绘制帧消费的挂起点击
    virtual void OnFrameTick(const UiFrameTick_& t) = 0;  // 绘制帧：悬停重算、改键轮询、绘制调度
    // ---- 生命周期 ----
    virtual void OnBattleStart() = 0;                     // 战斗开始/重置：清手势、悬停、滚动
    virtual void OnBattleEnd() = 0;
    // ---- 核心通知（核心→界面，替代现在直写 g_ui 的通知字段）----
    virtual void ShowNotice(const char* utf8, bool highlight) = 0;
    virtual void ShowSavedStamp(const char* stampUtf8) = 0;
    virtual void OnListChanged() = 0;                     // 界面自行从服务层拉取新列表
    virtual void OnRestoreStateChanged(bool busy, bool pending) = 0;
};
```

规则：

- 契约方法内允许堆分配（现状绘制帧同样用 `std::string`），但**禁止栈上大缓冲**；路径缓冲仍守 `kPathCap_=4MB` 堆规则。
- 契约方法不得被 `__except` 过滤器调用，只能在保护体内调用；过滤器仍只走 `GuardCrashFilter_`。
- 吞并判定归属界面（命中区域是几何概念）；但**存档键边沿去重与时机门禁判定归属功能**，界面收到键事件后调服务层 `WantsSaveEdge()`/`RequestSave()`，不得自判窗口。

## 5. 领域服务（BattleStoreService 草案）

public:

## 7. 持久化键归属

- 功能键（服务层读写）：`[Hotkeys] SaveKey`、`[Logging] MinLevel`。
- 界面键（HdNativeUi 自己读写）：`[Ui] BarX`、`BarY`。2026-10-14 起**已不影响绘制**：两套界面位置各自决定（战场外固定 `(8,8)`，战场内锚定战斗对话框右上角并每帧跟随），`Initialize` 不再读取它们；键保留不删，读写都不影响功能。
- 界面键（界面层共用）：`[Ui] OutsideBattlefield`——归界面层，HdNativeUi/FoldableBarUi 共用，由分发器 `UiPortDispatch_` 启动时读取（`IniReadIntUtf8Layered`，`default.ini` 出厂默认 + `user.ini` 覆盖）、由面板第一行「战场外」复选框写回 `user.ini`。`0`（默认）=战场内右上角折叠灯，`1`=战场外左上角固定条。
- 键名、节名、默认值全部不变；`user.ini` 只在玩家显式操作（等级点击、复选框勾选、改键）时写回，不自动改写。

## 9. 测试与验收边界

- 单元（不启动游戏、不真实 ABI、不占真实剪贴板）：
  - 服务层：列表扫描（fixture 目录）、`RequestLoad` 去重/generation 取消/窗口拒绝、文案目录映射、热键占用表、日志级别持久化失败保持原值（既有测试迁移+扩充）；
  - 界面层：NullUi 记录事件序列；HdNativeUi 的纯几何（UiLayout 回归既有）继续有效；
  - 契约：POD 事件结构 static_assert，防有人塞入带析构对象。
- 实机（用户执行）：步骤 2、4 后各抽查一次外观与存/读/改键/日志打包；步骤 5 用 `H3BS_UI_NULL` 变体验证不绘制、不吞输入（正式 DLL 默认战场内折叠灯，可用 `[Ui] OutsideBattlefield`/面板「战场外」复选框切到战场外固定条）；步骤 7 后抽查两套界面互切无残影、配置写回与重启后选择保持。
- 边界重申：单元测试不证明实机绘制正确，不证明恢复完整正确。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| SEH 函数内 C++ 对象展开（C2712）随搬移扩散 | 契约事件全 POD；钩子包装函数不持有需展开的局部对象；每步 0警告重建把关 |
| 虚调用开销/热路径 | 绘制帧一次虚调用，远小于现有 blt；输入钩子内仅一次判定调用，可忽略 |
| 线程规则被破坏（界面实现从别的线程调服务） | 契约注释硬性声明“仅游戏主线程”；跨线程仍走既有 Interlocked 投递；NullUi 单测断言调用序列单线程 |
| 恢复状态机搬移引入时序回归 | 步骤 4 单独提交；恢复维护决策纯测试（Keep/CancelBattleChanged/超时）先迁移并保持断言不变 |
| 文案目录搬移丢条目 | 目录做成静态表+遍历测试（每条 raw 至少命中一次或明确落入默认） |
| 契约膨胀成万能接口 | 每加一个方法必须在文档登记理由；禁止把绘制原语放进契约（那是 HdNativeUi 私有） |

## 11. 开放问题裁定（2026-10-10 用户已裁定，全部定稿）

1. **未来界面形态**：按建议——换皮肤（仍 HD 原生绘制）+ NullUi 薄契约；外部 Win32 工具等真需要时再扩展契约。
2. **界面选择方式**：**编译期单选**（非运行时 ini）。默认 HdNativeUi；NullUi 通过编译宏（`H3BS_UI_NULL`）选出，同一份 DLL 只含一套界面，无 ini 开关。**（2026-10-14 修订：玩家可选的两套界面改为同一 DLL + 运行期配置选择 `[Ui] OutsideBattlefield`，见第 7 步；NullUi 仍由编译宏 `H3BS_UI_NULL` 选出。）**
3. **BarX/BarY**：归界面层。位置是显示概念，换界面后新界面可忽略或自定义布局；键名、默认值不变。**（2026-10-14：两套界面位置各自决定，BarX/BarY 已不影响绘制，键保留不删，见第 7 步。）**
4. **迁移节奏**：五步分批，每步独立提交可回退；任一步实机异常即回退该步。
