# 专题：UI 与输入

> 来源：原《设计文档.md》字体高度布局节、§8、§15.1 保存窗口条目（2026-10-08 按用户裁定拆分）。
> 布局常量以 `modules/UiLayout.hpp` 与 `tests/UiLayoutRegression.hpp` 为准。

## 1. 实际字体高度布局（2026-10-07）

悬浮框保持 `(8,8)` 固定位置和原热键/改键/通知状态机。每次绘制在回调内取得现有 `H3SmallFont::Get()`，两行固定带高取 `max(24,font->height)`，连续存档行高取 `max(18,font->height)`；24/18 是设计下限而非字体假设，不在全局静态初始化加载字体。五处自研文字均保留原 MIDDLE_LEFT/MIDDLE_CENTER 对齐；首行以原 24px 带中心为锚向上下扩展，逻辑 `(8,8)` 不变，实际绘制/命中起点为 `max(0,8-(带高-24)/2)`。后续带和列表按新高度推进、在各自区域居中；触屏幕顶时优先夹紧避免裁剪，不能同时保持绝对原中心。字体不足设计下限时原几何完全不变。

绘制、列表背景、hover、按钮框、呈现/刷新、命中和战场夹紧共同使用同一运行布局快照；合成图尺寸改变会重建。源 `HB_bg.pcx` 仍验证 480x48，不改资源：每个原 24px 带保留 3px 上下金边、仅映射内部纹理到运行带高。起点改变时完整恢复旧两行带及窄列表区域；仅缩高而起点不变时恢复旧 480px 两行带尾区和窄列表尾区。原宽度和固定位置不变，因此异常超大字体仍可能超出屏幕，已有 blt 裁剪不等于完整可见保证。

`tests/UiLayoutRegression.hpp` 的纯 constexpr/static_assert 回归包含 16/22/30px 字体、设计下限、合成高度、列表各行上下界/空列表和纹理映射边界/默认恒等；生产命中调用同一纯函数，通过本项目 `build.bat /t:Rebuild` 编译验证。未运行新 exe 或绕过 360，未改 Hook 原版调用路径；构建与纯几何断言不代表中文字体插件、HD 呈现或鼠标实机验收。

## 2. 悬浮条（原 §8.1）

- 真正进入手动战斗后显示，快速战斗和结果界面隐藏；
- 左侧为刷新列表区域，右侧为存档快捷键；条下常驻当前场次普通列表，无展开/收起；
- 第一次显示在战场框外上方，避开远优对比面板；
- 最终接受界面固定左上角 `(8,8)`，两行 480×48（见第 3 节），不可拖动；改键时键框仍可见，普通列表不使用图片背景，宽136px、固定最多 30 行（2026-10-08 裁定，与同场保留条数一致；600 高度默认字体行高 18 时 8+48+30×18=596 恰好全部可见）；
- 位置自动限制在窗口内，分辨率变化后重新夹紧；
- 组件消费自己的鼠标事件，按钮、列表和拖动不得穿透到战场。

## 3. 日志等级横向单选列表与时机灯（原 §8.3.1，2026-10-07 当日两次改版）

- 2026-10-07 存读档时机灯：改键按钮左侧固定圆灯，中心 x=HotkeyX-16、半径7px；允许亮绿（64,230,112），不允许亮红（245,64,64），每次绘制实时重算。灯与改键绘制/命中共享 HotkeyX；左侧文字按实际字体宽度、GBK完整字符边界截短，不能盖灯。灯、存档、读档共享 CombatStorageWindow_（初始化、主战场、人类活栈、未提交动作、未在动作执行器或施法核心内、非自动/战术/结束）；读档额外只在游戏线程的外层消息返回边界执行。系统按键/列表点击到达时和实际处理时均门控：红灯操作静默丢弃，不提示、不排队等待变绿；读档确认后窗口失效同样静默取消。纯策略2048种布尔组合及灯位/颜色/字体高度几何纳入独立LogControls编译回归，游戏内显示与输入仍待用户实测。
- 时机灯误红修正：0x698A3C 是包含普通刷新tick的重入标志，473A00 内先置1、调用495C50、再清0；灯在495C50后置钩子及Blt内绘制时恰好读到1，因此不能作为存读档门禁。共享窗口删除该条件，不要求待令动画全部停止；保留 action==0 与4786B0实际动作执行深度，新增5A0140施法核心深度（thiscall、void、六个int参数），finally只维护深度且原版异常传播。英雄/生物施法在核心返回前均禁止，返回后重新开放人类待令窗口。状态变化仅写debug `[StorageWindow]`，记录action/executor/spell；未实机验收，第三方绕开原生施法核心的路径不承诺覆盖。
- 布局最终为固定两行悬浮框（480×48）。第一行横排五级"全部/调试/信息/警告/错误"（5×76px；配置值仍为 trace/debug/info/warn/error）与右侧打包日志按钮（x=392、宽84）；第二行显示存档状态与改键框。存档列表位于 y+48 下方，绘制和命中共享该原点。
- 底图直接改为 HB_bg.pcx 单张 480×48：从 HA_bg.pcx 原图正中裁取 `(100,250)` 起的 480×48 RGB 中段，不缩放，再按原 HB_bg 方法烘焙双层金边；中间 y=23..24 为暗金分隔线。生成脚本 `scripts/make_hb_bg.py` 自检尺寸、纹理和边框。
- 单选项固定五个，显示为"全部/调试/信息/警告/错误"，默认 `info`（与 `ParseLogLevel_` 及默认 ini 一致，配置仍使用英文值，未知文本一律回落 info，不因配置错误关日志）；当前项绿字（LIGHT_GREEN）+亮底，悬停浅色高亮；单元格用圆点标记表达单选语义，文字只显示中文等级名称。
- 选中即调 `SaveLogLevel_`：先写 `H3BattleStore.user.ini` 的 `[Logging] MinLevel`，成功才更新 `g_log_level`；失败提示「日志配置保存失败，等级未改变」并保留原等级。
- 交互契约：点单元格选中；等级块空位与条本体的左/右键均吞并不穿透战场；等级行右键不动作。悬停高亮按 WH_MOUSE 钩子与绘制帧 `H3POINT::GetCursorPosition` 双路刷新（面板 mouse-over 频率不可靠）。
- 打包沿用 H3Auto 的 LogPack.inc.cpp 和 LZMA SDK（Z7_ST 单线程编码）：最近五份本插件日志完整文件（2026-10-07 起收集模式与日志器同源：`g_log_base` = DLL 文件名去扩展名，即 `<基名>_*.log`；与 H3Auto 等其他插件同目录也只匹配自己的日志，DLL 被改名后依旧正确，基名缺失才退回 `H3BattleStore_*.log`），加 UTF-8 BOM 的 00_说明.txt，生成同目录 H3BattleStore_logs_日期_时间.7z，以 Unicode CF_HDROP 文件式复制到剪贴板。剪贴板失败保留已生成包并提示，不宣称复制成功。
- `DisableLog` 不进界面，仍以 ini 为准；战斗重置清悬停。两行固定矩形整块 blt，不再生成独立等级底图，不存在展开/收起状态。
- 按用户要求仅保留独立单元测试（Archive/Codec/LogControls），真实钩子 ABI 测试及布局探针源码、运行入口和临时产物删除。运行效果由用户实测，不以单元测试代替。
- 读档提交和回滚完成绘制后，只用 `H3BaseDlg::SendCommandToItem` 同步法术书 `0x7D8`、等待 `0x7D9` 与防御 `0x7DA` 的输入门禁：命令6/5、参数 `0x1000` 分别启用/禁用；法术书按原版条件（非战术、当前方有英雄且装备法术书、heroCasted==0或+0x13D74例外）决定，不清施法标志、不改魔力。2026-10-07日志显示未施法档保存/回读/恢复均casted=0/0和mana=220/0，但C键未转换为按钮消息，旧同步漏掉0x7D8；高置信为残留禁用门，实际按钮状态待用户复测。debug SpellControl记录条件与enabled/shaded，纯策略真值表单元测试覆盖已施法/无英雄/无书/战术/例外。逆向证据见H3Note《战斗英雄一回合施法限制逆向笔记》§8。不调用含回合推进和自动施法副作用的完整 `0x477C00`。普通日志记录 `+0x132B4` 控制门值及空格 KEY_DOWN/UP 前后的 action、当前部队和底栏状态，供用户实机区分"未提交防御"与"已提交但未轮转"。

## 4. 列表、确认与快捷键（原 §8.2/§8.3）

- 只列当前场次，新的在上；无记录显示"无存档"；
- 单击记录先弹确认框，确认文字必须包含具体时间和"当前这场未保存的进度会丢掉"；
- 取消确认不改变战斗，普通列表保留；
- 右键删除单条记录，删除成功后更新索引；
- 读档期间禁用重复点击，成功后保留当前场次的全部记录。

出厂默认 `G`，并排除 HoD 插件已占用的 `Z`；只接受未被原版战斗、SoD_SP、打铁助手和 HoD 占用的单字母。等待改键时按键只用于改键；Esc 或点击外部取消。配置分为随包的 `H3BattleStore.default.ini` 和玩家层 `H3BattleStore.user.ini`，运行时只写玩家层。

## 5. 存读档时机窗口（原 §15.1 条目）

- 2026-10-06 用户裁定并实现：保存窗口 = 轮到该玩家行动（`isHuman[currentActiveSide]`）且战斗处于手动正常进行（可读、dlg、非结束、非自动、非战术）。窗口外按存档键静默丢弃（2026-10-07 改为红绿时机灯反馈），不做等待动画、不加输入锁。尾部action/path不参与拦截，仅由诊断采样记录；2026-10-07确认原H3API两成员各左移一字节，旧日志不能作为其原生语义实证，诊断现改取native偏移（见《04-恢复事务与校验》）；一次物理按键经 `g_saveEdgeConsumed` 闩锁只触发一次保存（双输入源去重）。当前另检查动作执行器深度、施法核心深度、action==0及顶层主战场，阻断已提交动作和施法过程；不再按0x698A3C拒绝普通待令刷新动画；该组合不声称覆盖所有HD或第三方瞬态。

## 6. 输入路径与绘制目标（原 §8.4，2026-10-05 21:17 实测修订）

2026-10-07 空格误入改键修正：原版 `MOUSE_BUTTON` 与 `ITEM_COMMAND` 共用 `0x200`，热键按下/松开可经 `0x456540/0x455E70` 原地改写消息为 `0x200/0xC或0xD/itemId`。旧消息兜底仅按当前光标位置处理，会把防御等原生控件命令误当悬浮框点击。现将 `0x200` 全部透传，悬浮框点击只由已有系统 WH_MOUSE 钩子记录并在绘制帧消费；消息层仅更新悬停。原版调用前复制键盘消息，调用后插件只读副本，不还原原版消息；读档请求/完成和换场取消临时改键。LogControls 增加纯消息路由回归，不构造 ABI 或布局探针。最新实机日志恢复后 control=1、wait/defend enabled=1/shaded=0，后来 rebind=1 且无系统改键点击记录，符合旧兜底误入；当时没有 itemId 取证，修复后的实际行为仍由用户验证。

实机战斗会话确认的事实与最终方案：

- **消息钩子 0x473A00 可用**：KEY_DOWN（cmd=1，subtype 为 H3 键码，G=34）、KEY_UP（cmd=2）、MOUSE_OVER（cmd=4，坐标在 subtype/itemId 且与 position 镜像）均到达。早期"收不到"的判断源于测试会话未真正进入战斗，已作废。
- **双输入路径并存互备**：消息钩子处理键盘保存/改键；系统钩子（游戏窗口线程 WH_KEYBOARD/WH_MOUSE + 绘制帧 GetAsyncKeyState 兜底）负责点击吞并、拖动与消息时序无关的兜底。Windows VK（G=0x47）与 H3 键码（34）分开映射。
- **命中吞并**：悬浮条/列表区域内的按键鼠标事件在系统钩子内返回 1 吞掉，不透传给战场；恢复确认等重逻辑留在绘制帧执行。钩子以战斗管理器可读且未结束为守卫，非战斗界面不介入。
- **保存门槛（实测修正）**：`action` 四元组在玩家空闲悬停时持续非零，不再作为保存拒绝条件（仅记录观察值）；保存拒绝条件保留 finished、自动战斗、tacticsPhase、`actionUndergoing`、187 个移动格非空、消息返回值 2。
- **绘制目标（后续实测修正）**：在小尺寸 `H3LoadedPcx16` 上合成文字，锁定 DirectDraw backbuffer 拷贝像素并用 `H3Redraw` 呈现。禁止直接 DD Blt（HD_VGL2 崩溃）或对大 screenPcx16 调 TextDraw（ZCN2 崩溃）；早期 screenPcx16 直接绘字方案已作废。
