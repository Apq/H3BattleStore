# 专题：指纹与存档索引

> 以当前代码为准（`Entry.inc.cpp` 的 `BattleInitialFingerprint_/BattleFingerprint_/TryCaptureCombat_`、`BattleArchive.inc.cpp` 的 `ArchiveStore`）。历史设计沿革见[变更记录](../变更记录.md)。

## 1. 场次指纹

### 1.1 计算时机与冻结

指纹在 `0x462600`（战斗开始）HiHook 的**原版函数调用之前**由 `BattleInitialFingerprint_` 计算一次并冻结（`g_preBattleKey_` + `g_preBattleManager_`）。每场开始时 `BattleReset_` 先清空。此后保存/读档统一经 `BattleFingerprint_` 取冻结值，且要求当前 mgr 指针与采集时一致；否则报「未取得本场战斗的战前指纹，请重新进入战斗」。战中任何变化都不重算。

### 1.2 实际参与计算的输入

以下字段按固定顺序拼接后哈希；整数均为小端 4 字节。2026-10-08 用户最终裁定：地图身份只用标题，不加场景文件名（[BattleFingerprint.hpp](../modules/BattleFingerprint.hpp) 供生产与单测共用）：

- `u32 0x3250414D`（字节 `MAP2`，仅标题的地图身份方案标记，不是 codec 版本）；
- 地图标题/游戏名：`H3Main::mapInfo.mapName`（对象 `+0x1FB3C`，字符指针 `+0x1FB40`），编码为 `u32 字节长度 + 原始字符串字节`。该字段也用于 HD 游戏名/目录名，热座下可能是玩家输入的游戏名；
- 场景文件名不读取、不编码，也不保留文件名为空的占位字段；仅地图文件改名不影响指纹。同标题地图由既有战斗开局输入继续区分，不额外引入文件名；
- 只读已加载局的内存，不开磁盘地图/存档文件、不取地址值、不重编码。保留大小写、空白、颜色码及原生中文字节；空名编码长度 0，不替换为 `Unnamed`。不可读或字符串长度/容量/终止字节异常（要求 `Length()<=MaxLength()`，`Length()>0` 时还要求 `text[Length()]==0`）直接拒绝生成指纹，不以缺字段降级。标题采样上限 4MB，内容在堆上；

然后按原顺序追加以下战斗开局输入：

- 环境：`landType`、`specialTerrain`、`siegeKind2`（要塞等级，不是 +0x53A4 的可变门状态）、原始字节 `+0x53A8`、`+0x53A9`、`boatCombat`、`town` 指针空/非空（1/0）；
- 每侧（0..1）：`heroOwner`、hero 指针空/非空、前 7 个军队槽的 `army->type[slot]` 与 `army->count[slot]`（军队数据不可读直接失败，不降级）；
- 每侧英雄身份（v5 增补，指针不可读按 -1 编码）：`id`、`experience`、`level`、19 个穿戴槽 `bodyArtifacts[slot].id`；
- 城镇身份（v5 增补，不可读按 -1）：`number`、`type`、`owner`。

哈希用 Windows CryptoAPI `CALG_SHA_256`，输出 64 位小写十六进制。

刻意不加入：战斗实例随机值（2026-10-06 裁定不稳）、损血、站位、回合、障碍、自动施法标志等一切战中可变量。穿戴与英雄身份字段用于阻断"同色同阵容的不同英雄、穿戴不同强度不同"的互读。

### 1.3 开局时间核查（2026-10-08）

本轮在 SoD 的已加载局、原生存档头和保存/加载路径中，未确认到“创建这一局的时间”字段，暂不加入时间输入：

- `H3Main::date` 是当前游戏日/周/月，会随过天变化，不是开局时间；
- 场景浏览数据的 `FILETIME` 是文件时间，不是当前局身份，也不位于已加载 `H3Main::mapInfo` 中；
- NH3API 的 `cUniqueSystemID`（`H3Main+0x1F644`，32 字节）确实被原生保存/加载，但原生开局逐 DWORD 清首字节，HD 另有整段清零路径，不能将它当作开局时间或可靠的局唯一标识；
- 本次启动/读档时间、当前存档文件名或文件修改时间不加入：它们会使同一局重打/改名/重启后的指纹变化。

以后仅在确认某字段随战略存档序列化、同一局读档/重打/跨进程保持相同、重新开局生成新值后再接入。当前同一地图重新开局仍可能撞档；地图名不等于局唯一 ID。静态调查不证明所有游戏/MOD 都没有此字段。

### 1.4 撞档语义

地图标题及战斗开局输入完全相同则指纹相同、共用一份列表；恢复预检仍完整生效（撞档不豁免任何档案自身校验）。同标题地图、相同地图的两次开局仍可能碰撞，不宣称地图身份能隔离每一局。2026-10-08 地图身份从无到 `MAP1`（文件名+标题）再收缩为 `MAP2`（仅标题，用户裁定），每次输入变更旧档 key 均失配，文件保留在磁盘但不再出现在新列表；不做旧指纹回退匹配、迁移或删除。codec 仍为 v6，文件帧未改变。

## 2. 存档文件帧（当前格式）

每条记录一个 `.hbs` 文件，小端布局（`kHeaderBytes=152`）；目录索引只保存该帧的 metadata，完整 payload 不常驻内存：

```text
u32  magic 0x31425348（盘上四字节 48 53 42 31 = "HSB1"，实测核验）
u16  formatVersion = 1
u16  headerSize = 152
64B  battleKey   ASCII 小写 hex
64B  targetKey   ASCII（当前恒 64 个 '0' 占位，时刻级指纹未启用）
u64  timestampUtcMs（UTC 毫秒，排序与身份权威）
u32  sequence（当前恒 0，撞名改用文件名后缀，不再用序号）
u32  sectionCount
每段：u32 id + u32 length + u32 crc32 + 字节负载
u32  全文件 CRC32（尾 4 字节）
```

当前固定 8 个段，缺一整档拒绝（`capture is missing a required section`）：

| id | 段 |
|---|---|
| 1 | battle（管理器标量/RNG） |
| 2 | stacks（42 槽数值） |
| 3 | squares（187 格） |
| 4 | obstacles（障碍载荷） |
| 5 | log（战斗日志文本） |
| 6 | heroes（英雄副本标量） |
| 7 | relations（关系容器） |
| 8 | spells（部队法术 deque） |

格式上限保持不变：最多 16 段、单档 64MB，段 id 合法范围 1..16。文件层不识别的版本、段 id 或损坏内容只影响当前列表可见性/读档判定，未知坏档保留在磁盘，不自动删除，不能把未知文件当作可清理对象。

## 3. 落盘与索引行为

- 文件名：`<指纹64hex>_本地yyyymmdd_hhmmss.hbs`；同指纹同秒撞名追加 `_2`、`_3`…（`MakeArchiveName` 的 attempt 循环）。文件名时间仅是显示标签，身份与排序以头内 UTC 毫秒为准。
- 提交写入：先写唯一 `*.tmp` → `FlushFileBuffers` → `MoveFileExW(MOVEFILE_WRITE_THROUGH)` 提交到唯一的新 `.hbs` 名称；不得覆盖旧档，不称为“原子替换”。任一步失败删除 tmp、不产生条目。`ArchiveStore::Save` 返回实际提交路径（含撞名后缀）。
- 保存成功后按需回读刚提交的档案：Load + CRC + 逐段原始字节比较 + 重新解码（`TryCaptureCombat_` 的 readback 阶段）；回读不过按 `persisted-unverified` 结束，不当成功。
- 列表扫描：逐个临时读取并校验文件，扫描结果仅保留 metadata（记录路径、battleKey、targetKey、时间和序号），不缓存所有档案 payload；点击读档时再按记录路径加载并校验完整内容。未知格式、段 id、坏 CRC 或无法解析的文件可以从当前列表隐藏并写日志，但必须保留在磁盘，不自动删除。排序按 `timestampUtcMs` 倒序，其次 `sequence` 倒序。
- 保留策略：所有档案永久保留，不执行每场条数或最近战斗场数的自动清理；同秒 `_2`、`_3` 等旧命名冲突后缀上限属于命名容量，不是档案保留上限。
