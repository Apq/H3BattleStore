## 1. 目标与范围

### 1.1 目标

- 把独立插件 `D:\GitHub\H3\H3BattleCrashFix` 的三个**防崩型 HiHook** 并入本插件，玩家侧只留一个 DLL 与一套配置。
- 保持宿主单翻译单元结构：模块文件仍然扁平（无 namespace 包裹），由 `H3BattleStore.cpp` 的包含点包进 `namespace crashfix { … }`——与 `namespace autoassist`、`namespace h3bs` 同款，规避 MSVC「include 进命名空间的文件再开同名 namespace 会破坏同块后续文件查找」（C2065）这个已复现的坑。
- 复用宿主既有基建，零 shim：日志（`LogInfo` 等）、分层 ini（`IniReadIntUtf8Layered`）、`kPathCap_`、CrashGuard 四层防御（`GuardRegisterHook_` / `GuardCrashFilter_` / `GuardVerifySodBytes_`）全部用宿主的。

### 1.2 非目标

- **不改任何修复语义**：地址常量（`0x466710` / `0x43E790` / `0x43E720`）、结构偏移（`OFS_TYPE=0x34`、`OFS_SIDE=0xF4`、`OFS_ACTIVE_SPELLS_DURATION=0x198`、障碍向量 `+0x13D5C/+0x13D60`、元素 `0x18`、def `+0x00`、duration `+0x10`）、法术编号（丧心病狂 59 / 蛊惑 60）、`__try` 铠甲语义与日志标签（`[障碍]` / `[光环]` / `[阻止清理]`）一律逐字保留。
- 不为旧独立插件 H3BattleCrashFix 做共存检测：用户已裁定只保留并入版，但文档统一写明「不要再同时加载 `H3BattleCrashFix.dll`」（同地址双挂）。
- 不在本插件里新增战斗逻辑：三处修复只做「异常吞并 + 安全默认跳过」，不参与正常路径的数值或流程。

## 5. 顺带修掉的一个宿主老缺陷（`IniWriteKeyUtf8`）

迁入过程中给 `[CrashFix]` 写分层配置回归时，发现宿主的 `IniWriteKeyUtf8` 在**重写已有文件**时会把每个既有键的值原地截断：

- 根因：匹配键名的写法把 `'='` 临时写 0 再 `IniTrim_`，等号前的空格被写成 0，恢复 `'='` 也补不回那个空格，于是该行在 `strlen` 口径下被截断——`MinLevel = debug` 变成 `MinLevel`，重读即回落默认。每写一次吃掉一个既有键的值（反复写还能写出重复键行）。
- 玩家侧表现：用悬浮条改一次日志级别，`user.ini` 里其它键（热键、界面选择等）的值被逐个吃空，自定义热键静默失效。
- 修法：从已修同源实现（H3Space / H3RndNew 侧）移植——**匹配时不得改写源行**，改为「向前跳过等号前的空白算出键长 + `strncmp` 比较」。移植后该函数与已修版**逐行等价**（归一化注释后 117 有效行全等）。
- 回归：`tests\CrashFixTests.cpp` 的配置用例（同一文件第二次写入后断言首个键的值仍在）+ 独立探针 `ini-probe`（写入→重读往返，四种序列）。修复前该用例红、修复后绿。
