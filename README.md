# H3BattleStore — 战场存档

《英雄无敌 III》SoD HD Mod 插件。目标是在手动战斗中保存当前战斗时刻，并在同一场战斗里恢复；当前构建已接入同场战斗的受限恢复。

> 实验构建，精确恢复尚未实机验收。当前实现以存档替换当前战场，包括障碍集合、部队与法术队列、关系容器、攻城资源及鹰眼记录；当前战场拓扑不必与存档相等。重新采集不一致会尝试回滚；回滚验证失败或写入中异常立即终止，不继续运行未知状态。文件和受控原语测试不能证明伤害轨迹、战后结果和 UI 正确，勿用于不可丢失的战斗进度。研究方案见 [恢复事务与校验](docs/04-恢复事务与校验.md)。

## 功能

- 在战斗空闲、等待玩家操作时保存当前时刻，而不是只保存战斗开始状态。
- 每回合首次进入玩家等待窗口自动存档一次，写入 `自动\<回合>.hbs|.json`，只保留最近30个有效自动档。读档成功后重新武装，同回合新自动档覆盖旧轨迹。
- 手动 G 键写入 `手动\<回合>_<编号>.hbs|.json`，永不覆盖、永久保留。两列均按回合数倒序，手动列同回合按编号倒序；两列及读档确认均显示不带后缀的实际文件名：手动如 `25_3`，自动如 `25`。
- 快照包含损血、数量、站位、行动状态、法术持续、英雄副本魔力、障碍、城墙、战斗日志等字段；2026-10-06 起并采集游戏线程 TLS 当前种子与 `0x67FBE4` 播种镜像；当前 codec v8 保存障碍 kindId、锚点、五标量、DEF 名和派生格集合，重建增删并重算格索引，同时保存可达阴影缓存及原生路径块；新增双方战斗英雄的战争机器装备（穿戴槽13–16的 ID/subtype），与部队一并恢复、回滚和校验，避免死弹药车恢复后仍享受免扣弹。v7及更早档一律拒绝读取，文件不自动删除。完整恢复仍待实机验证。
- 悬浮条显示在战场画面上方，不占用战场格子。
- 存档记录作为常驻普通列表显示；左键选中记录并确认后请求读档，只有外层玩家待令窗口允许提交。
- 右键列表区域由插件吞并，不执行删除或其他动作，也不穿透到战场。
- 默认折叠界面锚定战场右上角，移到灯上展开、移出收起；界面可在面板第一行用「战场外」复选框或 `[Ui] OutsideBattlefield` 切换（默认战场内折叠灯；勾选后用战场外左上角 `(8,8)` 常显悬浮条）。控制条为 `480×48` 两行，不可拖动。第一行横排日志等级单选项、「战场外」复选框和“打包日志”按钮（等级项与复选框宽度按字体实测、项间紧凑排列），第二行显示状态与改键框；两行控制条下新增「手动存档／自动存档」标题行，下方两列正文各宽168px，自动列固定右移184px；各自最多显示20行（不足按实际条数），超过20条时独立增加14px滚动条。自动保存刷新数据时保持滚动位置。列表行高固定按 `max(18,font height)`，不按窗口高度动态计算。滚轮每 120 刻度滚动 3 行并支持高精度累积，箭头滚动 1 行，轨道点击翻页 20 行，滑块可拖动。
- 点击悬浮条右侧的快捷键名称可以改键，默认存档键为 `G`，避开 HoD 插件占用的 `Z`。
- 日志等级单选列表五个单元格“全部/调试/信息/警告/错误”（2026-10-14 紧凑化：单元格宽度按字体实测文本宽 + 左右内边距，标记槽 1 字符，选中态高亮底 + 亮绿字），默认“调试”（`debug`；只有用户明确要求才改回 `info`，缺失/未知值代码 fallback=`debug`；配置仍保存为 `trace/debug/info/warn/error`）：点击单元格即写入 `H3BattleStore.user.ini` 的 `[Logging] MinLevel` 并立即生效；写入失败提示失败且等级不变。当前项绿色加亮。右侧“打包日志”沿用 H3Auto：最近五份完整日志压成 `.7z`，并以文件形式复制到剪贴板；成功提示包含反馈QQ群 1042362808 / 740338251 和 QQ 712999712，联系方式也写入包内说明。两行底图直接由 HA_bg.pcx 正中 480×48 中段加同款金边生成 HB_bg.pcx。**注意**：这个按钮是本项目自带的（2026-10-12 起），与 2026-10-15 合并打铁助手时**移除**的「打铁设置面板 → 帮助页」里的同名按钮是两回事；合并版只在悬浮条这一处提供打包日志。
- 界面选择（2026-10-14）：两套界面（战场内右上角折叠灯 / 战场外左上角常显悬浮条）同在一个 DLL，由 `[Ui] OutsideBattlefield` 决定（`default.ini` 出厂默认 `0`=折叠灯，`user.ini` 可覆盖），也可在面板第一行勾选「战场外」复选框即时切换；勾选即写回 `user.ini` 并立即生效，写盘失败时界面保持不变。
- 存档文件独立于游戏战略地图存档，不会出现在原版读档列表中。
- 手动档写 tmp、flush 后提交新文件，自动档原子替换同回合旧档并保留最近30个。两种格式由 `user.ini [Store] saveFormat=binary|json` 决定（默认binary）；改配置需重启，两后缀互不可见、不迁移。codec v8、二进制容器v2、JSON帧v1；单档64MB，未知坏档隐藏但留盘。

自动保存失败本回合不重试，下一回合再尝试。

### 打铁助手（H3Auto）功能已并入本插件（2026-10-15）

- 合并进同一个 DLL，**不要再同时加载 H3Auto.dll**：两者会抢同一批钩子地址（`0x600430`、`0x4786B0`）与面板素材，轻则热键冲突、重则崩溃。请在插件目录删除旧的 `H3Auto.dll` 并只加载「战斗中存档」。
- 战斗中的默认热键（`H3BattleStore.user.ini [Hotkeys]` 可改）：`F9` 启停打铁（全手动/自动切换）、`J` 单次接管当前部队、`P` 打开打铁设置面板。改键只在战斗中生效。
- 打铁设置面板提供方案 1–5（各编号独立草稿）、法术规则、力盾、攻击魔法等页面；面板素材为 `pcx\HA_*.pcx`，文案可用 `lang\zh-CN.ini` 覆盖。
- **方案库与战斗存档是两套东西**：方案库存的是"打铁策略方案"，JSON v7 每槽一文件，路径 `<游戏根>\Games\<地图名>\Auto\<16位hex>.json`（回退 `Games\Auto` → DLL 同目录），最多保留最近 30 场；战斗存档存的是战场时刻快照，仍在 `Games\<游戏名>\战场存档\<指纹>\` 下。
- 协作机制随之改为**同 DLL 直连**（原跨 DLL 的 patcher 变量 `H3BattleStore.RestoreEpoch.v1`/`BusyQuery.v1`/`BeforeAutoAction.v1` 不再需要）：读档确认/恢复期间打铁不提交自动效果；读档成功后打铁清运行态、回全手动并按 `F9` 继续，移动/近战游标从头开始。历史约定与边界见[协作与防冲突](<docs/10-H3Auto协作与防冲突.md>)，本次合并的完整设计见[H3Auto 功能移植](<docs/11-H3Auto功能移植.md>)。
- 打铁助手**不含**打包日志功能（本项目已有，见下文悬浮条第一行）——源插件帮助页里的「打包日志」按钮与相关文案随合并一并移除，帮助页只保留开源地址行（2026-10-16 起日志等级设置也从帮助页移除：战场存档界面悬浮条第一行已有日志等级单选列表，不再有两个入口）；开源地址显示/复制的是本仓库 `https://github.com/Apq/H3BattleStore.git`。

### 战斗崩溃修复（H3BattleCrashFix）已迁入本插件（2026-10-15）

- 用户裁定：战斗类修复统一随本插件走；**随身空间（H3Space）同日起不再携带该功能**——升级本插件与随身空间请同批部署，避免战斗崩溃保护断档。
- 三个防崩型 HiHook（整函数 `__try`，异常吞并落盘，安全默认 = 跳过本次原函数调用）：**[障碍]** `CombatMgr::RemoveObstacle @0x466710`（障碍 def 双重释放崩溃，恢复事务经 `kObstacleRemove` 直呼该地址同样受保护）；**[光环]** `UpdateAuraLinks @0x43E790`（独角兽抗魔光环 × 丧心病狂/蛊惑写坏关联）；**[阻止清理]** `Vector::FindAndRemove @0x43E720`（损坏 vector 越界读保护）。
- 配置：`H3BattleStore.default.ini [CrashFix]`（`DisableObstacle`/`DisableAura`，`0`=启用修复默认，`1`=不挂钩），可在 user.ini 覆盖。
- 守卫前缀 `CrashFix.*`（与 `BattleStore.*`/`AutoAssist.*` 互不混淆，崩溃日志直接读归属）；守卫数 23→26，上限 32。
- **不要再同时加载旧的 H3BattleCrashFix.dll**（同地址双挂）；同日也别再从随身空间侧期待该功能。

## 安装与部署

需要 32 位 Heroes III SoD 和 HD Mod 插件环境。

将以下文件放入（**2026-10-15 起目录名改为 `热血插件`**，与 H3RndNew 等插件共用同一目录；历史上曾用 `战场存档`）：

```text
<游戏目录>\_HD3_Data\Packs\热血插件\
├── H3BattleStore.dll
├── H3BattleStore.default.ini
├── 使用说明.txt
├── pcx\HB_bg.pcx            本项目悬浮条底图
├── pcx\HA_*.pcx             打铁助手面板素材（9 个，2026-10-15 起随本插件分发）
└── lang\zh-CN.ini           打铁助手界面文案覆盖（内置默认表在主 DLL 内，删掉此文件即回落内置）
```

素材目录名 2026-10-15 由 `img\` 改为 `pcx\`（与 `H3MegaDesc`、`H3Space` 同规）。DLL 以 `pcx\` 为主路径，并保留旧 `img\` 目录的兜底：老安装目录里没改组时也能正常显示，日志会提示「素材取自旧目录 img\」。更新到新素材包后，游戏目录里残留的旧 `img\` 目录可以删掉（只是旧副本，删前确认目录里没有别的插件的东西）。

然后打开 HD Mod 启动器，在插件列表中启用「战斗中存档」。

当前项目的部署脚本使用以下游戏目录（取仓库根 `H3Env.ps1` 的 `$H3GameDir`，可用环境变量 `H3_GAME_DIR` 临时覆盖）：

```text
D:\Heroes3\Heroes3_2026.10.09\_HD3_Data\Packs\热血插件\
```

可执行（编译/部署统一入口，三选一）：

```bat
build.bat             仅编译
deploy.bat            仅部署
build_and_deploy.bat  编译 + 部署一步完成
```

## 使用方法

1. 进入手动战斗后，战场右上角显示状态灯，鼠标移到灯上展开悬浮条（默认界面；勾选第一行「战场外」后改为左上角常显悬浮条）。
2. 按悬浮条显示的快捷键保存当前战斗时刻；保存成功时会短暂显示时间反馈。
3. 进入战斗会自动加载本场列表，不自动恢复；手动刷新、手动新存档和换场把列表滚动回顶部；自动保存刷新保持两列滚动位置。左键记录按 `scroll.first + 可见行号` 定位并确认后读档，点击悬浮条左侧只刷新列表。列表只缓存扫描得到的元数据，不缓存所有档案载荷。
4. 右键列表会被吞并但不执行动作、不穿透战场；存档没有删除操作。
5. 改键按钮左侧的圆灯实时显示存读档时机：绿灯允许，红灯不允许。红灯时存档键和读档点击静默丢弃，不弹提示、不等动画结束后补执行；绿灯时读档仍需确认，且只在外层消息边界提交。
6. 仅鼠标点击右侧快捷键名称进入改键，按允许的字母改键；按 `Esc` 取消改键。空格、防御和等待命令不触发改键；读档及换场取消临时改键状态，保留已保存的快捷键。
7. 悬浮框第一行是日志等级横向单选列表，点选即保存并生效；当前项绿色加亮。第一行右侧的「战场外」复选框切换界面：不勾（默认）是战场内右上角状态灯 + 悬停展开，勾选后是战场外左上角常显悬浮条；勾选即写入 `H3BattleStore.user.ini` 的 `[Ui] OutsideBattlefield` 并立即生效，写盘失败则界面不变。最右侧“打包日志”生成插件目录内的 `.7z` 并复制为文件，可粘贴发送。

插件只在手动战斗中显示悬浮条。保存窗口限定为"轮到玩家本方行动且战斗正常进行"（isHuman[currentActiveSide]、非战术/非自动/非结算）；其他时机圆灯为红色，存读档操作静默丢弃，不等待、不屏蔽输入。尾部action/path不参与拦截，旧H3API成员存在错位，诊断已改读原生偏移；当前只排除已提交的动作、实际动作执行器和施法核心内部的保存/恢复，不要求待令时的普通动画停止，不使用通用刷新忙碌标志。

## 存档与配置文件

战斗存档在地图/游戏名目录下再单独放一层固定子目录：`<游戏目录>\Games\<游戏名>\战场存档\`，不再与过天自动档混放。单人遭遇战的游戏名即地图名（含 `{~c}` 颜色码原样保留），热座局为玩家输入的游戏名，随机图等无名的局落在 `Games\Unnamed\战场存档\`。2026-10-11 起存档按**战斗指纹分目录**组织：`战场存档\<64hex 指纹>\手动\<回合>_<编号>.hbs|.json`（自动档在 `自动\<回合>.hbs|.json`，保留最近30个有效档）。编号是同回合内存档序号：从 1 起、取同回合已有最大编号 +1，自然位数无上限不补零；`(回合, 编号)` 唯一。列表按 (回合, 编号) 两段数值倒序（先比回合、再比编号，均为整数比较，不受位数影响）。**存档格式双轨可选**：`user.ini` 新增 `[Store] saveFormat=binary|json`（默认 `binary`，即既有二进制 `.hbs`；改配置需重启游戏生效）——`json` 时存 `.json`（逐字段原子展开、缩进 2 空格、可直接阅读/手改/diff，帧版本独立从 1 起）；两种后缀互不可见、互不迁移，旧档留盘不删，切回配置即可再见。旧平铺命名 `战斗指纹_yyyymmdd_hhmmss.hbs` 的存量档留盘不删、不进读档视野。列表与读档确认显示无后缀文件名；保存成功提示按当前本机时区显示（含夏令时），内部仍保留 UTC 毫秒用于身份校验。切换时区不重命名已有文件，也不改变其可读性。指纹只用战斗中恒定的字段计算：**已加载局的地图标题/游戏名**（2026-10-08 最终裁定只用标题，带长度前缀，不读取或编码场景文件名）、地形/攻城/水战、双方军队槽兵种与开局数量、双方英雄 id/经验/等级、**双方 19 个穿戴槽宝物 id**、城镇编号/类型/归属；损血、站位、回合等会变的字段不参与。未确认可靠的随档开局时间，因此不加入启动/读档时间或文件时间；同地图不同开局仍可能撞档。本次输入变更使旧战斗档不再出现在新列表，文件保留、不回退匹配。2026-10-06 起更换指纹输入后，旧版存档的 key 失配不再出现在列表（文件保留不删）。目录由插件每次保存时读取引擎当前局游戏名决定（与 HD `UI.Ext.ScenarioMgr.Folders` 同一来源 `0x699538+0x1fb40`），读不到时退回 `Games\战场存档\`。保存成功后刷新悬浮条下方的常驻列表，第一项即刚存的档（同回合编号最大）。

其余运行时文件位于插件目录：

```text
H3BattleStore.user.ini    玩家配置（首次使用时可不存在）
H3BattleStore_*.log       插件日志
```

`H3BattleStore.default.ini` 是随插件分发的默认配置，升级时可能被覆盖；玩家改动应写在 `H3BattleStore.user.ini`。

```ini
[Logging]
DisableLog=0
MinLevel=debug

[Hotkeys]
SaveKey=G
; 2026-10-15 合并打铁助手（H3Auto）后新增，可在 user.ini 覆盖：
ToggleManual=F9       启停打铁（全手动/自动）
OneShotManual=J       单次接管当前部队（只允许单个字母）
OpenSettings=P        战斗中打开打铁设置面板（只允许单个字母，且不得与 OneShotManual 相同）

[General]
; 同样来自打铁助手：DisableOnStart=1 进战斗时不自动开启打铁；
; LastProfile=面板默认选中的方案编号 1-5（勾号确认时写回 user.ini）；
; Language=界面文案语言（对应 lang\<语言>.ini）。
DisableOnStart=0
LastProfile=1
Language=zh-CN

[Store]
; binary（默认，.hbs）或 json（可读可手改可 diff 的 .json）；改后需重启游戏生效。
saveFormat=binary

[CrashFix]
; 2026-10-15 迁入的战斗崩溃修复（源 H3BattleCrashFix；用户裁定归本插件）。
; 0=启用修复（默认）；1=不挂钩对应修复；改后需重启游戏生效。
DisableObstacle=0
DisableAura=0
```

悬浮条单选列表选中等级时只写 user 层的 `MinLevel`，不改动 `H3BattleStore.default.ini`；本次调整不自动改写玩家 ini，原有配置覆盖优先级不变。`DisableLog` 仍以 ini 为准，界面不提供开关。日志文件最多保留30个的策略不变，它与手动档永久保留、自动档保留30个相互独立。

**2026-10-15 修复 `user.ini` 写入器老缺陷**：旧写入器在重写已有文件时会把**每个既有键的值原地截断**（`MinLevel = debug` 变成 `MinLevel`），于是用悬浮条改一次日志级别，`user.ini` 里其它键（自定义热键、界面选择等）的值会被逐个吃空、静默回落默认——现在写入不再破坏既有键（同文件多键往返有单测 `tests\CrashFixTests.cpp` 兜住）。若你以前遇到过"改了日志级别后热键失效"，原因就是这个，重设一次即可。

## 构建

目标为 `Release|Win32`。全量验证必须经过批处理入口：

```bat
build.bat /t:Rebuild
```

默认界面为折叠式（屏幕右上角状态灯，悬停展开完整悬浮框）；另一套战场外左上角常显条同在这个 DLL 里，由玩家配置 `[Ui] OutsideBattlefield` 或面板「战场外」复选框选择（见上文"功能"）。编译变体只剩两个：

```bat
build.bat /t:Rebuild                         默认：两套悬浮条界面都在，由配置选择；同时包含打铁助手界面（部署目标）
build.bat /t:Rebuild /p:H3BS_UI_NULL=1      Null：只记日志，不绘制不吞输入（诊断/自动化用，不部署）；
                                            与打铁助手源的 H3AUTO_UI_NULL 同口径，不含打铁面板实现
```

折叠式语义：收起时只剩状态灯（绿=可存读/红=不可），鼠标移到灯上自动向左向下展开完整悬浮框（两行控制条 + 标题行 + 手动/自动双列表），鼠标移出展开区域自动收起；展开后交互与旧界面一致，收起态只放行灯区内输入（存档键、改键等键盘路径不受折叠影响）。

输出文件：

## 测试

独立单元测试改用 **Catch2 v3（amalgamated，`third_party/catch2/`，参照 H3Space 工程）**；不启动游戏、不安装钩子、不操作真实剪贴板：

```powershell
.\tests\run-unit-tests.ps1
```

- 运行方式：五组用例各自由 `cl`（`/nologo /EHsc /std:c++17 /utf-8 /W4 /wd4505 /O2`）连同 `catch_amalgamated.cpp` 独立链接成 `tests\unit-tmp\<组名>.exe` 后运行，**退出码非零即失败**；`catch_amalgamated.cpp` 只编译一次并缓存为 `tests\unit-tmp\catch2.obj`（源码更新才重编），避免每套重复编译大文件。
- LogControls 的 fixture 目录经环境变量 `H3BS_TEST_FIXTURE` 传入（Catch2 接管命令行解析，不再用 argv 传参）。
- 断言口径：原 `Expect`/`Check` 的"失败即止"对应 `REQUIRE`，非致命累计对应 `CHECK`，原描述文本经 `INFO` 附加到失败报告；`REQUIRE_MESSAGE`/`CHECK_MESSAGE` 由测试文件自行用 `INFO`+断言包装（本版 amalgamated 未提供 `*_MESSAGE` 变体）。
- Archive：文件格式、CRC、提交写入、元数据扫描与未知坏档不误删（12 个 `TEST_CASE`）。
- Codec：构造快照的编解码、数据范围与恢复策略校验（6 个 `TEST_CASE`）。
- LogControls：默认 debug（中文"调试"）、五级持久化重读、写入失败保留等级、实际日志写入过滤、阶段/结果分级、重复限频与计数（含计时回绕）、原生消息路由、最近五份完整日志的 LZMA 打包、Unicode CF_HDROP 载荷与剪贴板失败处理（3 个 `TEST_CASE`）。
- UiPort：NullUi 契约——输入事件全透传、无绘制/服务副作用、读档 fail-closed（无界面确认框只告警丢弃）、通知与生命周期日志顺序、事件结构 POD 断言生效。测试用最小类型 stub，不链接 H3API（3 个 `TEST_CASE`）。
- AltTail：ALT 退后落点判定——只认尾端正后方一格，行边缘/越界/无退后能力/攻击或超出射程一律拒绝，非 ALT、单格宽与 AI 方保持原版（7 个 `TEST_CASE`）。

## 诊断日志（2026-10-06）

默认 `MinLevel=debug`（中文“调试”）保留启动版本/配置、场次、存读档请求、提交/验证/结果、实际路径和快照摘要，并记录完整阶段耗时、部队摘要、段 CRC、原始/改写消息、控件状态及动作执行前后；正常空闲不输出绘制心跳，重复稳定心跳只在“全部”（`trace`）每30秒输出。只有用户明确要求时才改回 `info`；代码读取到缺失或未知等级一律 fallback=`debug`，不因配置错误关闭日志。构建标识为 `battle-diag-ammo-equipment-v7`，启动行带编译时间和进程 ID。级别不是事后补录，反馈须在发生问题前开启 debug。

- `[Input]`：系统/游戏/绘制帧来源、down/up、重复标志、改键锁和抑制原因。
- `[Op N]`：操作编号、阶段、阶段耗时、总耗时、失败方/槽位、是否已进入写内存阶段。
- `[State op=N]`（debug）：动作四元组、原生 any_action_taken、路径非零格数量、回合、当前部队、战术/自动/结算状态；这两个原生尾部字段不被解释为忙碌判据。
- `[Command]` / `[InputState]` / `[Execute]`（debug）：原始和原版改写后的消息、itemId、控制门值、等待/防御门禁、动作执行前后与轮转；记录离散事件，不记录鼠标移动。
- `[Wait op=N]`：等待开始、原因变化、超时/取消、输入解锁及拦截计数。
- `[Snapshot]` / `[Section]`：快照摘要、八段长度和 CRC32。
- `[Archive]`：实际落盘路径和冲突修正后的序号；保存后重新读盘、CRC 校验、字节比对和解码。
- `[Restore]` / `[Verify]`：危险资源操作前后、恢复后重新采集的逐段比较、首个差异字节偏移。
- `[Render]`：本次实际标记的部队帧数量；`restore.render-creatures`、`restore.render-field`、`restore.render-log`、`restore.rng`、`restore.verify`区分提交后的原版调用步骤。
- `[Guard]`：SoD 数据指纹门卫、钩子异常、未处理异常模块/偏移和退出收尾。

`ok` 只表示保存文件回读通过；`serialized-equal` 只表示已编码字段相等，不能证明随机调用轨迹及HD/其他插件状态一致。当前 `rejected` 表示校验拒绝或验证失败后已回滚；`partial-write` 表示写入中异常，没有任意异常回滚保证，立即停止而不继续战斗。日志无 DETACH 收尾也可能是强杀，不能单凭这一点归因到本插件。

首轮实测请用可丢弃的测试战斗：空闲保存 → 普通部队移动/损血 → 左键记录确认 → 核对数量、损血、站位、当前部队与日志 → 重复相同动作核对伤害/随机轨迹 → 正常结束核对结果。动画中保存应拒绝；改键不得保存；取消读档不得改战斗。连续读档、双格兵、等待/防御、魔力/法术及列表滚动/右键吞并须另测。召唤/镜像、容器变化、攻城资源与两种阴影设置均须另做真机恢复验收，离线通过不等于运行时成功。
