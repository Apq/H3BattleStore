# H3BattleStore — 战场存档

《英雄无敌 III》SoD HD Mod 插件。目标是在手动战斗中保存当前战斗时刻，并在同一场战斗里恢复；当前构建已接入同场战斗的受限恢复。

> 实验构建，精确恢复尚未实机验收。当前实现以存档替换当前战场，包括障碍集合、部队与法术队列、关系容器、攻城资源及鹰眼记录；当前战场拓扑不必与存档相等。重新采集不一致会尝试回滚；回滚验证失败或写入中异常立即终止，不继续运行未知状态。文件和受控原语测试不能证明伤害轨迹、战后结果和 UI 正确，勿用于不可丢失的战斗进度。研究方案见 [设计文档第16节](设计文档.md)。

## 功能

- 在战斗空闲、等待玩家操作时保存当前时刻，而不是只保存战斗开始状态。
- 同一场战斗支持多条存档，列表按时间倒序显示。
- 快照包含损血、数量、站位、行动状态、法术持续、英雄副本魔力、障碍、城墙、战斗日志等字段；2026-10-06 起并采集游戏线程 TLS 当前种子与 `0x67FBE4` 播种镜像；当前 codec v6 保存障碍 kindId、锚点、五标量、DEF 名和派生格集合，重建增删并重算格索引，同时保存可达阴影缓存及原生路径块。v5及更早档一律拒绝读取，文件不自动删除。完整恢复仍待实机验证。
- 悬浮条显示在战场画面上方，不占用战场格子。
- 存档记录作为常驻普通列表显示；左键选中记录并确认后请求读档，只有外层玩家待令窗口允许提交。
- 右键删除存档。
- 悬浮框固定左上角 `(8,8)`，`480×48` 两行，不可拖动。第一行横排日志等级单选项和“打包日志”按钮，第二行显示状态与改键框；下方存档列表宽 136px、最多 10 行。
- 点击悬浮条右侧的快捷键名称可以改键，默认存档键为 `G`，避开 HoD 插件占用的 `Z`。
- 日志等级单选列表五个单元格“全部/调试/信息/警告/错误”，默认“信息”（配置仍保存为 `trace/debug/info/warn/error`）：点击单元格即写入 `H3BattleStore.user.ini` 的 `[Logging] MinLevel` 并立即生效；写入失败提示失败且等级不变。当前项绿色加亮。右侧“打包日志”沿用 H3Auto：最近五份完整日志压成 `.7z`，并以文件形式复制到剪贴板；成功提示包含反馈QQ群 1042362808 / 740338251 和 QQ 712999712，联系方式也写入包内说明。两行底图直接由 HA_bg.pcx 正中 480×48 中段加同款金边生成 HB_bg.pcx。
- 存档文件独立于游戏战略地图存档，不会出现在原版读档列表中。
- 每场最多保留 30 条记录，磁盘最多保留最近 30 场战斗。

## 安装与部署

需要 32 位 Heroes III SoD 和 HD Mod 插件环境。

将以下文件放入：

```text
<游戏目录>\_HD3_Data\Packs\战场存档\
├── H3BattleStore.dll
├── H3BattleStore.default.ini
├── 使用说明.txt
└── img\HB_bg.pcx
```

然后打开 HD Mod 启动器，在插件列表中启用「战场存档」。

当前项目的部署脚本使用以下游戏目录：

```text
D:\Heroes3\Heroes3_2026.10.07\_HD3_Data\Packs\战场存档\
```

可执行（编译/部署统一入口，三选一）：

```bat
build.bat             仅编译
deploy.bat            仅部署
build_and_deploy.bat  编译 + 部署一步完成
```

## 使用方法

1. 进入手动战斗后，战场上方会出现悬浮条。
2. 按悬浮条显示的快捷键保存当前战斗时刻；保存成功时会短暂显示时间反馈。
3. 进入战斗会自动加载本场列表，不自动恢复；新增存档立即刷新且最新在首位。左键记录并确认后读档，点击悬浮条左侧只刷新列表。
4. 右键存档条目可以删除它。
5. 改键按钮左侧的圆灯实时显示存读档时机：绿灯允许，红灯不允许。红灯时存档键和读档点击静默丢弃，不弹提示、不等动画结束后补执行；绿灯时读档仍需确认，且只在外层消息边界提交。
6. 仅鼠标点击右侧快捷键名称进入改键，按允许的字母改键；按 `Esc` 取消改键。空格、防御和等待命令不触发改键；读档及换场取消临时改键状态，保留已保存的快捷键。
7. 悬浮框第一行是日志等级横向单选列表，点选即保存并生效；当前项绿色加亮。右侧“打包日志”生成插件目录内的 `.7z` 并复制为文件，可粘贴发送。

插件只在手动战斗中显示悬浮条。保存窗口限定为"轮到玩家本方行动且战斗正常进行"（isHuman[currentActiveSide]、非战术/非自动/非结算）；其他时机圆灯为红色，存读档操作静默丢弃，不等待、不屏蔽输入。尾部action/path不参与拦截，旧H3API成员存在错位，诊断已改读原生偏移；当前另检查动作执行器深度和已知执行标志，排除其内部的保存/恢复。

## 存档与配置文件

战斗存档在地图/游戏名目录下再单独放一层固定子目录：`<游戏目录>\Games\<游戏名>\战场存档\`，不再与过天自动档混放。单人遭遇战的游戏名即地图名（含 `{~c}` 颜色码原样保留），热座局为玩家输入的游戏名，随机图等无名的局落在 `Games\Unnamed\战场存档\`。文件名 `战斗指纹_yyyymmdd_hhmmss.hbs`，同指纹同秒多次保存追加 `_2`、`_3` 后缀。文件名按保存时的本机时区生成；列表、保存提示和读档确认按当前本机时区显示（含夏令时），内部仍保留 UTC 毫秒用于排序和身份校验。切换时区不重命名已有文件，也不改变其可读性。指纹（v5）只用战斗中恒定的字段计算：地形/攻城/水战、双方军队槽兵种与开局数量、双方英雄 id/经验/等级、**双方 19 个穿戴槽宝物 id**、城镇编号/类型/归属；损血、站位、回合等会变的字段不参与。2026-10-06 起更换指纹输入后，旧版存档的 key 失配不再出现在列表（文件保留不删）。目录由插件每次保存时读取引擎当前局游戏名决定（与 HD `UI.Ext.ScenarioMgr.Folders` 同一来源 `0x699538+0x1fb40`），读不到时退回 `Games\战场存档\`。保存成功后刷新悬浮条下方的常驻列表，第一项即刚存的档。2026-10-06 本机旧目录中的4条档已迁入新子目录并核对SHA256，内容不变；插件只扫描新目录，不自动迁移其他安装的旧档。

其余运行时文件位于插件目录：

```text
H3BattleStore.user.ini    玩家配置（首次使用时可不存在）
H3BattleStore_*.log       插件日志
```

`H3BattleStore.default.ini` 是随插件分发的默认配置，升级时可能被覆盖；玩家改动应写在 `H3BattleStore.user.ini`。

```ini
[Logging]
DisableLog=0
MinLevel=info

[Hotkeys]
SaveKey=G
```

悬浮条单选列表选中等级时只写 user 层的 `MinLevel`，不改动 `H3BattleStore.default.ini`；`DisableLog` 仍以 ini 为准，界面不提供开关。

## 诊断日志（2026-10-06）

默认 `MinLevel=info` 保留启动版本/配置、场次、存读档请求、提交/验证/结果、实际路径和快照摘要；正常空闲不输出绘制心跳。问题复现前切换“调试”（`debug`），保留完整阶段耗时、部队摘要、段 CRC、原始/改写消息、控件状态及动作执行前后；重复稳定心跳只在“全部”（`trace`）每30秒输出。构建标识为 `battle-diag-20261007-log-audit-v6`，启动行带编译时间和进程 ID。级别不是事后补录，反馈须在发生问题前开启 debug。

- `[Input]`：系统/游戏/绘制帧来源、down/up、重复标志、改键锁和抑制原因。
- `[Op N]`：操作编号、阶段、阶段耗时、总耗时、失败方/槽位、是否已进入写内存阶段。
- `[State op=N]`（debug）：动作四元组、原生 any_action_taken、路径非零格数量、回合、当前部队、战术/自动/结算状态；这两个原生尾部字段不被解释为忙碌判据。
- `[Command]` / `[InputState]` / `[Execute]`（debug）：原始和原版改写后的消息、itemId、控制门值、等待/防御门禁、动作执行前后与轮转；记录离散事件，不记录鼠标移动。
- `[Wait op=N]`：等待开始、原因变化、超时/取消、输入解锁及拦截计数。
- `[Snapshot]` / `[Section]`：快照摘要、八段长度和 CRC32。
- `[Archive]`：实际落盘路径和冲突修正后的序号；保存后重新读盘、CRC 校验、字节比对和解码。
- `[Restore]` / `[Verify]`：危险资源操作前后、恢复后重新采集的逐段比较、首个差异字节偏移。
- `[Render]`：本次实际标记的部队帧数量；`restore.render-creatures`、`restore.render-field`、`restore.render-log`、`restore.rng`、`restore.verify`区分提交后的原版调用步骤。
- `[Guard]`：SoD 数据指纹门卫、钩子异常、未处理异常模块/偏移和退出收尾。

`ok` 只表示保存文件回读通过；`serialized-equal` 只表示已编码字段相等，不能证明随机调用轨迹及HD/其他插件状态一致。当前 `rejected` 表示校验拒绝或验证失败后已回滚；`partial-write` 表示写入中异常，没有任意异常回滚保证，立即停止而不继续战斗。日志无 DETACH 收尾也可能是强杀，不能单凭这一点归因到本插件。

首轮实测请用可丢弃的测试战斗：空闲保存 → 普通部队移动/损血 → 左键记录确认 → 核对数量、损血、站位、当前部队与日志 → 重复相同动作核对伤害/随机轨迹 → 正常结束核对结果。动画中保存应拒绝；改键不得保存；取消读档不得改战斗。连续读档、双格兵、等待/防御、魔力/法术及删除列表尾部须另测。召唤/镜像、容器变化、攻城资源与两种阴影设置均须另做真机恢复验收，离线通过不等于运行时成功。

## 兼容边界

- 目标版本是 Heroes III SoD 32 位 x86；硬编码地址针对目标 SoD EXE。
- 不修改原版战略地图存档系统。
- 不依赖 ERA、ZCN2.dll、H3.TextColor.dll 或其它插件。
- 与打铁助手、远优对比、人性化读档可同时加载，但本插件不读写打铁助手的方案存档。
